# Risk Register: SSH brute-force detection with threat-intelligence enrichment

> Module 4 · Version 1.0 · 2026-11-20
> v0.1 (2026-10-13) planned the controls; this version records what was built in Sessions 1–7, with evidence.
> Scores use the course template's Scales sheet (bottom of this file).

## Scope

- **Problem:** an SSH bastion host is continuously targeted by bots guessing passwords. Without detection the attack is invisible.
- **What the project builds:** a system that reads sshd logs, recognises attack patterns with Sigma rules, checks the source IP against a MISP list of malicious IPs and raises alert severity on a match; Prometheus/Alertmanager/Grafana alert when the pipeline itself stops.
- **How it is built:** in Docker, in a protected Git repository, with an AI agent (Claude Code) writing configuration under the owner's rules, automated checks (CI) and an automated AI reviewer before every merge.
- **Out of scope:** no IP blocking; nothing exposed to the internet; only synthetic logs created by the owner.

## Residual score justification

- **R-01** (16 → 4): Direct push is closed by the platform and tested; five required checks, including the AI reviewer, must pass on an up-to-date branch. Likelihood reaches 1, the Session 1 target. Impact is unchanged: if review is bypassed anyway, the damage is the same.
- **R-02** (20 → 6): Three layers (local hook, CI, push protection) and encryption at rest make a leak unlikely; keys are lab-scoped and were rotated when no longer needed.
- **R-03** (16 → 8): A broken or stale rule fails a test before merge. Impact is unchanged: a rule that slips through still leaves the attack unseen.
- **R-04** (6 → 2): Every PR states its risk IDs; the reviewer flags the ones that do not.
- **R-05** (20 → 12): The threshold rule was not built. Per-event rules catch invalid-user guessing, but repeated failures against existing accounts raise no alert, so likelihood stays at 3.
- **R-06** (12 → 8): Spraying over non-existent usernames alerts on every attempt; spraying over valid usernames does not. Higher than the planned 4 because no distinct-user count exists.
- **R-07** (10 → 10): Fallback from v0.1 applied: the correlation was not built, residual returns to inherent; root password logins are alerted as a partial compensating control.
- **R-08** (12 → 6): Known-bad sources are ranked first, so the analyst sees them first. This is the outcome Session 6 asks the enrichment to change.
- **R-09** (12 → 8): Parser regressions fail in CI before merge, and a stopped, unhealthy or back-pressured pipeline raises an alert in Grafana and Alertmanager. Residual likelihood stays 2 because a pipeline that runs but receives no sshd lines (for example a misconfigured log source) is not alerted, and Alertmanager has no notification receiver; both gaps are accepted for lab scope.
- **R-10** (9 → 4): Warninglists, age-out and de-duplication remove most stale or benign indicators; the remaining false positives affect a single alert, not trust in the whole system.
- **R-11** (15 → 5): A moved tag cannot be used; updates wait 7 days and pass CI.
- **R-12** (12 → 4): Fork code never runs with secrets or a write token without approval.
- **R-13** (16 → 8): Images are scanned, pinned, signed and verifiable; one unscanned image (Logstash) keeps likelihood at 2.
- **R-14** (9 → 6): The owner now sees what Shodan sees; acting on a finding is still manual.
- **R-15** (6 → 4): Outage is visible immediately and has a documented manual fallback.
